## Current operational limits

The runtime is a local-owner service with loopback host, token, and origin checks, not authenticated multi-user memory. It stores prompts and results on this Mac. Model calls receive the latest six completed turns, including their steering, for the same agent in the selected conversation and explicitly selected dependency results. A one-time snapshot preserves the selected project's original Tay history in the first runtime conversation; up to twelve original messages are available to Tay alone. The original file remains unchanged, and later conversations begin empty. This is bounded context recall, not universal memory across the ecosystem.

Steer, Pause, and Cancel wait for the current blocking model request to return or fail. Superseded, paused, and cancelled outputs are discarded. Steering causes another request with the saved instructions; it does not modify a provider's already-running generation or undo charges. Status text makes this delay visible.

One process owns the queue database, and one worker shares the legacy execution lock. Closing the browser leaves accepted work running while the server stays alive. Restart recovery occurs when the runtime is next initialized; interrupted active work requires Resume. Credentials and billable consent do not survive that restart.

This runtime can generate discussion, drafts, and plans. It has no exposed tool/action executor, including when the existing interface is in Execute mode. Authenticated authority, action-specific approvals, and execution enforcement must be added together before consequential workflows are enabled. A model's statement that it performed an action is never execution evidence.

2. Add a shared authenticated session and memory boundary for text and voice, keeping agent identity independent of the chosen model.
3. Connect objective lifecycle and handoff records to the Operating Graph, then implement server-authorized tools with approvals tied to the exact action.
4. Add automatic model routing preferences, compatible fallback, and measured routing outcomes within privacy and cost policy.
5. Add KJ-led Forge workflow jobs and a provider-agnostic 3D adapter through the same queue, authority, and asset history.
6. Introduce safe parallel execution only after resources, tool permissions, dependency rules, and conflict handling are explicit; validate large backlogs and history pagination.
