# Transcenlutions Arcade release record — 17 October 2026

## Release scope

Transcenlutions Arcade adds four original local games—**Crown Grid, Prism Sort, Orbit Link and Lumen Run**—to the existing platform. The web entry is `/arcade`, redirecting to `/arcade/index.html`. The module supports touch and keyboard play, local progress, larger text, stronger contrast, reduced motion and optional synthesized sound. It has no account requirement, ads, purchases or payment SDK. Local progress is not cloud identity, an entitlement or a hosted leaderboard.

The same game assets support a standalone HTML export and an Android wrapper. This release does not claim 100 built games. See the [product README](../../products/arcade/README.md), [research record](../research/google-play-games-2026-10-17.md), [Android README](../../android/arcade/README.md) and [draft Play listing](../../android/arcade/release-listing.md).

## Build and workflow constraints

- `npm run test:arcade` runs the arcade checks; `npm run build:arcade` produces `dist/arcade/Transcenlutions-Arcade.html` from local assets.
- [Launch Gate](../../.github/workflows/launch-gate.yml) includes arcade validation while retaining the inherited platform checks. The existing [Security Gate](../../.github/workflows/security.yml) remains required. A local result is not a completed remote gate.
- [Arcade Android build](../../.github/workflows/arcade-android.yml) uses a standard public-repository GitHub runner with read-only repository permissions. Its job is disabled for a private repository. No paid runner is configured.
- Android validation requires the preinstalled licensed SDK components. The workflow does not accept SDK licenses or install missing SDK packages automatically; a missing component fails the build.
- The proposed release package is `com.transcenlutions.arcade`; debug builds use `com.transcenlutions.arcade.debug`. These identifiers are not proof of Play registration.
- Expected successful-build outputs are a CI-signed debug APK, an **unsigned** release AAB, checksums and lint reports. The AAB requires owner-controlled upload signing before submission. The CI debug certificate is not a stable production signing identity.
- The Android wrapper bundles local assets, declares no Android permissions, blocks network navigation and exposes no native JavaScript bridge. Physical-device verification is still required.

No registration payment, paid runner, provider credit purchase or new paid service is part of this release workflow. No spending or acceptance of owner account agreements has been completed by this release record. Public runner/artifact generation remains contingent on the repository and workflow conditions above.

## Google Play readiness and remaining steps

The **connected Play Console account inspected in this session showed developer enrollment/signup**, which blocks publication through that observed account. This finding applies only to the inspected account; it does not establish that the owner or Transcenlutions lacks another developer account.

1. **Resolve the publisher account.** Use an existing authorized developer account or complete organization-appropriate enrollment, required verification and owner agreements. New registration may require Google's one-time fee; it has not been paid here. See [Play Console registration requirements](https://support.google.com/googleplay/android-developer/answer/6112435) and [Play Console](https://play.google.com/console/).
2. **Complete source and build gates.** Record the release commit, passing Launch/Security/Android run URLs, artifact digests and release version. Install the verified APK on a device and test all four modes, airplane mode, progress persistence, background/resume, Back behavior, resizing, large fonts and accessibility. Confirm that the final permission and network behavior matches the listing.
3. **Establish owner-controlled signing.** Configure Play App Signing and protect the upload keystore and credentials outside source control. Sign the release AAB with the authorized upload key. See [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756).
4. **Complete the listing and declarations.** Review the draft title, descriptions, screenshots, app icon and contact details. Publish a reachable privacy-policy URL and accurately complete Data safety, app access, ads, content rating, target audience and any applicable declarations from the final build. See [Data safety requirements](https://support.google.com/googleplay/android-developer/answer/10787469). The no-ads/no-accounts design does not itself complete these forms.
5. **Follow the account's testing and release requirements.** If this is a personal account created after 13 November 2023, Google's documented production-access process requires at least 12 continuously opted-in closed testers for 14 days before applying for production access. This is conditional on the account type and history, not a universal launch timetable. See [testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465). Record the actual account's eligibility and track status.
6. **Submit and verify.** Submit only the reviewed, signed artifact through the authorized account, then record Google's review outcome and inspect the public listing and installation. Until those observations exist, Play publication remains **PENDING**.
